# Исправление 47 переводов и продолжение full_v2

По присланному логу сохранены 4124 из 4171 переводов. Повторная генерация с
512 токенами оставила 47 ошибок. В приложенном файле видны длинные повторения
междометий и ошибки JSON. Увеличение лимита токенов проблему не решило.

## Запуск на поде

Загрузить `translation_fix_v1.zip` в корень проекта через VS Code. Выполнить
из `/home/jovyan/sticker_search`, когда annotation workers уже остановлены:

```bash
python -m zipfile -e translation_fix_v1.zip .
bash scripts/apply_translation_fix.sh
```

Первый шаг CPU-only: добавить только отсутствующие переводы и выполнить
строгий merge. Ожидается `Added 47 assistant corrections on CPU; complete
4171/4171.` и `Merged 4171 rows: runs/full_v2/translations/queries_ru.jsonl`.
Затем скрипт автоматически запускает `run_gpu.sh --from index`: вычисление
признаков, обучение адаптеров и dev-оценка EN/RU. CUDA используется на этих
последующих этапах. Сетевые загрузки не нужны.

При ошибке исправления дальнейший запуск остановится. Логи:
`runs/logs/translation_fix_v1.log`, `runs/logs/full_v2_from_index.log`.
Повторный CPU-запуск идемпотентен. Весь wrapper повторно не запускать после
завершения обучения: существующий best.pt защищён от перезаписи. Для повторной
оценки использовать `bash scripts/run_gpu.sh --from evaluate`.

Отдельное применение только CPU-исправления:

```bash
python -m sticker_search.repair_translations   --queries data/catalog/labels/queries_en.jsonl   --output runs/full_v2/translations
```

## Что сохраняется и проверяется

- Исходные 4124 успешных записи сохраняются байт в байт в начале своих shards.
- Исправление сверяет hash входа с сохранённой конфигурацией и все поля
  исходной строки каждого из 47 запросов, включая split и positive_item_ids.
- Оригинальные конфигурации и error logs сохраняются; повторное применение
  пропускает уже добавленные переводы. Прерванное между shards применение
  можно повторить.
- `translation_provenance` отличает перевод VLM от исправления ассистентом.
  `translation_reviewed=false`, `human_reviewed=false`. Никакая запись не
  выдаётся за независимую человеческую разметку.
- Итоговый аудит записывается в
  `runs/full_v2/translations/translation_corrections_audit.json`.

Переводы подготовлены по исходному тексту запроса, без просмотра целевой
картинки, выдачи или метрик. Из 47 строк 33 относятся к train, 7 к dev и 7 к
test. Разбиение не менялось. 16 строк помечены ambiguous: это приблизительная
передача звуков или неоднозначное междометие. Три смайлика оставлены буквально.
Результаты RU-поиска следует описывать как оценку на машинных переводах с
исправлениями ассистента. Нужна отдельная человеческая проверка, особенно
неоднозначных строк; полнота файлов не равна качеству переводов.

Присланный Markdown содержит изменённое экранирование и завершающий символ
`a`. Он сохранён как исходное свидетельство, а не JSONL для импорта. Поля
source всех 47 строк сверены с ранее сохранённым полным каталогом; строки
неудачной генерации не использовались как корректные переводы.

## Проверка кода

CPU-тесты используют реальные исходные запросы и синтетические успешные
переводы; это проверка восстановления файлов, а не качества модели.
Проверены покрытие 4124→4171, сохранение разбиений/меток/байтов, происхождение,
повторный merge, идемпотентность, частично применённый патч и отказ при
несовпадающих входах. Всего 21 тест пройден, включая прежние проверки
восстановления разметки и маршрутизации этапов. GPU-запуск нового этапа
на поде по состоянию на подготовку патча ещё не подтверждён.
