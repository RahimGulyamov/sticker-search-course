# Диагностика слабого качества full_v2

Прогон на поде завершён: 30914 изображений, 4171 исходный запрос и 4171
перевод, 5766 train-строк. Лог содержит 10 эпох, наибольшее dev NDCG@5 среди
обученных эпох достигается на эпохе 4 (0.0123014).

| Метод | NDCG@5 EN | NDCG@5 RU | Hit@10 EN | Hit@10 RU |
|---|---:|---:|---:|---:|
| image | 0.0197 | 0.0031 | 0.0411 | 0.0066 |
| hybrid | 0.0033 | 0.0007 | 0.0115 | 0.0033 |
| lexical | 0.0127 | 0.0000 | 0.0148 | 0.0000 |
| learned | 0.0134 | 0.0112 | 0.0263 | 0.0181 |

Значения округлены в присланной консоли. Обучение помогло RU по сравнению с
image, но ухудшило EN. Среднее EN/RU NDCG@5 составляет примерно 0.0114 для
image и 0.0123 для learned; средний Hit@10 при этом ниже. Утверждение об общем
улучшении поиска пока не обосновано. Снижение loss после лучшей эпохи без
роста dev совместимо с переобучением, но не устанавливает его причину.

## Запуск

Загрузить `retrieval_diagnostics_v1.zip` в корень проекта на поде, затем:

```bash
python -m zipfile -e retrieval_diagnostics_v1.zip .
bash scripts/diagnose_full_v2.sh
```

Используются сохранённые эмбеддинги. Модели не загружаются; обучение и
индекс не изменяются. Скрипт CPU-only, нужен установленный NumPy и Pillow.
Вычисления по полному каталогу могут занять несколько минут; прогресс
показывается каждые 32 dev-запроса. Доступ в интернет не нужен.

Результат для передачи обратно: `runs/full_v2/retrieval_diagnostics.zip`.
В него входят диагностика, предыдущие EN/RU dev-метрики/кейсы, история и
конфигурация обучения. Скрипт откажется перезаписывать готовую диагностику.
Если уже существует `diagnostics_v1`, отдельный запуск модуля допускает
новый путь через `--output`.

## Проверяемые гипотезы

1. Шкалы cosine similarity для query–image и query–text могут различаться.
   Посмотреть средние/разброс скоров, положение известного positive и
   качество caption/OCR как отдельных веток.
2. Перенормировка весов по наличию OCR/описания может давать предпочтение
   определённым группам изображений. Сравнить текущий hybrid и linear_fixed,
   где сохраняются веса 0.65/0.25/0.10 при отсутствующих нулевых ветках.
3. Некоторые изображения могут часто попадать в выдачу для разных запросов.
   Посмотреть frequent_top1, unique_top10_items, распределение источников.
4. Русские запросы могут терять смысл при переводе или быть слабо представлены
   энкодером. Посмотреть EN/RU cosine и пары с низкой близостью; это показатель
   согласованности эмбеддингов, не автоматическая оценка правильности перевода.

Проверяется небольшой фиксированный набор альтернатив: RRF с весами
image/caption/OCR = 0.95/0.05/0, 0.80/0.20/0 и 0.80/0.15/0.05, константа 60.
RRF складывает обратные ранги, а не исходные cosine scores. Отсутствующий
текст не получает случайного места в этой ветке и даёт нулевой вклад.
Все сравнения выполняются на dev и полном каталоге. Test не оценивается.

`summary.json` содержит парный bootstrap разности NDCG@5 с image по group_id,
чтобы переводы и запросы одной группы не считались независимыми наблюдениями.
Доверительные интервалы описательные; они не скорректированы на выбор лучшего
метода из нескольких. Для окончательного вывода после выбора подхода нужна
отдельная test-оценка и человеческая проверка релевантности. В исходном протоколе
неразмеченные альтернативные стикеры считаются нерелевантными, поэтому низкие
known-positive метрики не заменяют просмотр выдачи.

После диагностики выбрать следующий опыт по результатам: настройка смешивания,
очистка проблемной ветки или более слабая адаптация. Новый результат нельзя
объявлять улучшением до запуска на поде. На момент подготовки проведены пять
CPU-тестов на синтетических эмбеддингах: формула старого hybrid, отсутствие
текста в RRF, dev-only оценка, контроль порядка векторов и версии энкодера.
