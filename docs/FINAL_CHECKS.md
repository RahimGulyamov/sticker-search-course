# Зафиксированный выбор и финальные проверки

## Что показал retrieval_v3

| Метод | Dev NDCG@5 EN | Dev NDCG@5 RU |
|---|---:|---:|
| image, прежний baseline | 0.019662 | 0.003133 |
| learned, full_v2 / epoch 4 | 0.013390 | 0.011213 |
| RRF 0.80/0.20 | 0.021943 | 0.005486 |
| RRF с поправкой caption | 0.017603 | 0.004748 |
| RRF с поправкой caption/OCR | 0.018670 | 0.005384 |
| RRF с поправкой всех веток | 0.014232 | 0.004027 |
| Родной CLIP на EN | 0.020863 | — |

Поправки не улучшили основной RRF. Родной CLIP на EN дал близкий результат
к мультиязычному энкодеру; парная разность NDCG@5 = 0.001201, 95% CI
[-0.007180, 0.008743]. Средний cosine между двумя энкодерами для одинаковых
EN-строк — 0.9647; это не доказывает отсутствие всех ошибок, но эксперимент
не дал оснований менять энкодер.

Для русскоязычного демо выбран `learned`, checkpoint `runs/full_v2/adapter/best.pt`,
эпоха 4. Это лучший наблюдавшийся RU dev NDCG@5 среди выполненных опытов.
Сам checkpoint ранее выбирался по объединённому EN/RU dev. Архитектура:
замороженные признаки CLIP, residual query/image adapters rank 64 и обучаемые
веса трёх веток. Нет утверждения, что он лучше на EN или статистически значимо
лучше baseline: RU-разность с image имеет 95% CI [-0.002685, 0.019814].

Низкие метрики и смысловые ошибки машинных RU-переводов остаются ограничением.
Полнота переводов после CPU-патча не означала их смысловую проверку. Финальный
отчёт должен описывать это явно. Не улучшать модель по результатам следующей
test-оценки; все результаты новых вариантов до сих пор относились к dev.

## Команда на поде

Загрузить `final_checks_patch.zip` в корень проекта:

```bash
python -m zipfile -e final_checks_patch.zip .
bash scripts/run_final_checks.sh
```

Скрипт:

1. Проверяет выбранную эпоху, соответствие checkpoint индексу и сохраняет
   хеши модели, индекса, запросов/векторов и кода **до** открытия test.
2. Оценивает `image`, `rrf`, `learned` на test EN и RU с одним полным каталогом.
3. Создаёт самодостаточный `runs/final_v1/review/search_review.html` с top-3
   по 18 фиксированным русским сценариям, включая открытки, отрицание и
   сложный сюжет. Это качественная проверка без gold-разметки.
4. Создаёт пять картинок по русским запросам, переводит их через уже
   загруженный Qwen, запускает FLUX и rembg/U2Net. Сохраняет исходные PNG,
   результаты с alpha, prompt, seed и время каждого запуска. Модель загружается
   заново для каждого примера; времена включают эту загрузку и не являются
   задержкой постоянно запущенного генеративного сервиса.
5. Упаковывает результаты и логи в `runs/final_v1/final_results.zip`.

Генерация выполняется на одной GPU последовательно, новые модели не
скачиваются. На поде должно оставаться доступным перенесённое generation bundle.
При ошибке этапа скрипт формирует архив с уже полученными файлами и `status.json`.
Ошибка начальной проверки артефактов останавливает выполнение до оценки.
Повторный запуск использует сохранённые test-результаты только при неизменных
зафиксированных файлах и коде, пропускает готовую галерею и успешные генерации.
Неуспешная генерация получает новую папку attempt, старые ошибки сохраняются.

`--skip-generation` предусмотрен только как явная диагностика: при таком
запуске генерация остаётся непроверенной и не должна заявляться выполненной.
Неоднородный alpha проверяется автоматически; качество вырезания фона требует
просмотра картинок, это не метрика сегментации.

## Демо в VS Code

```bash
bash scripts/run_demo.sh
```

Во вкладке Ports VS Code перенаправить порт 8501 и открыть его в браузере.
Сервис слушает 127.0.0.1. По умолчанию выбран обученный адаптер; в форме можно
сравнить его с поиском по изображению и RRF («Изображение и описание»).
Генерация включена, её нужно проверить до защиты. Для остановки — Ctrl+C
в терминале сервиса.

## Что ещё нужно завершить

- Разобрать test-метрики без подбора по ним новых параметров.
- Просмотреть HTML и пять пар original/sticker: объекты, эмоции, надписи,

- Подготовить итоговый PDF 10–15 страниц с реальными числами, графиками,
  ограничениями и отдельным описанием неудачных экспериментов.
- Опубликовать код в репозитории пользователя и добавить ссылку в ЛМС.
- Подготовить объяснение архитектуры, loss, разбиений и метрик для демо;
  синхронную защиту студент проходит самостоятельно.

Проведены четыре CPU-теста фиксации артефактов и возобновления: идентичный
повторный запуск, запрет изменения checkpoint, проверка выбранной эпохи/индекса,
отказ принимать test без заранее сохранённого выбора, проверка hash и
нетривиального alpha сгенерированного файла. Эти тесты используют фиктивные
байты для проверки управляющей логики; они не запускают модели и не
подтверждают качество генерации. Реальные test/галерея/генерация выполняются
на поде следующим запуском.
