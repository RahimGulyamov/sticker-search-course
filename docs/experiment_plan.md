# Эксперименты, которые дают материал для отчёта

Сначала проверить 500 VLM-аннотаций и скорость. Затем получить признаки одного
зафиксированного каталога. Гиперпараметры настраиваются только на dev.

| ID | Обучение | Признаки | Вопрос |
|---|---|---|---|
| B0 | Нет | OCR char TF-IDF | Насколько помогают точные надписи? |
| B1 | Нет | CLIP image + multilingual text | Что даёт готовая мультимодальная модель? |
| B2 | Нет | Изображение + VLM-caption + OCR | Помогает ли текст, извлечённый из изображения? |
| M1 | Residual adapters + fusion weights | Те же признаки B2 | Помогает ли обучение на предметной области? |

Первый CPU-пилот сравнивает только B1 и residual image/text adapters:
массовая разметка ещё не выполнена. Его метрики нельзя выдавать за B2/M1 полного каталога.

Возможные дополнительные эксперименты только после основного запуска:
1. Без OCR при остальных неизменных компонентах.
2. Без слабых синтетических запросов, только human-source train.
3. English-only supervision против EN+RU translations.
4. Multilingual SigLIP2 вместо выбранного CLIP.

Массовая разметка VLM не является обучением нашей модели. В проекте обучаются
проекции и веса fusion. Целевая функция связывает запрос с релевантным стикером;
генератор используется готовый. Это нужно чётко объяснять на защите.

## Качество данных

- Проверить 50–100 случайных аннотаций, фиксировать доли ошибок визуальных
  объектов, эмоций, OCR, перевода и выдуманных ситуаций использования.
- Отдельно проверить примеры с кириллицей и отрицанием.
- Переводы не должны превращать «не хочу» в «хочу», сарказм в искреннюю похвалу.
- Просмотреть крупнейшие группы dHash: это кандидаты на визуальную близость,
  а не гарантированно одинаковые стикерпаки.
- Пилотные OpenMoji-открытки показывать отдельной категорией; 240 макетов не
  означают 240 разных сюжетов. Реальные открытки пока отсутствуют.

## Интерпретация retrieval ошибок

Категории: подходящий объект, неверная эмоция; верная эмоция, другой объект;
непрочитанная надпись; неправильное отрицание; ирония; культурная отсылка;
анимация, потерянная при выборе первого кадра; похожая открытка другого события;
отсутствие нужного сюжета в каталоге; альтернативный релевантный, но неразмеченный ответ.

Примеры выбирать по детерминированной случайной выборке и метрикам каждого кейса,
а не только удачные. Ручная категория ошибки заполняется после просмотра картинок.
Не считать каждый промах по одному source-positive доказанной семантической ошибкой.

## До финального отчёта

- Закончить GPU-разметку и отметить реальные версии/скорость.
- Проверить качество перевода и OCR; добавить независимые русские запросы.
- Провести сравнение B0/B1/B2/M1 по одному протоколу.
- Проверить FLUX и вырезание фона на реальном A100; сохранить минимум 5 примеров,
  включая неудачные маски. Измерить задержку генерации отдельно.
- Подготовить PDF 10–15 страниц на основе полученных чисел и графиков.
- Опубликовать код в собственном репозитории без токенов/чужих весов.
- Пройти синхронное демо: подготовленный код и записанный скринкаст его не заменяют.
