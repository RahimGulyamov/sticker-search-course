# Результаты диагностики и опыт retrieval_v3

## Подтверждённые результаты full_v2

Все сравнения ниже — dev, 608 EN и 608 RU запросов, каталог 30914 изображений.

| Метод | NDCG@5 EN | NDCG@5 RU | Среднее EN/RU |
|---|---:|---:|---:|
| image | 0.019662 | 0.003133 | 0.011397 |
| hybrid | 0.003289 | 0.000708 | 0.001999 |
| learned, лучшая эпоха 4 | 0.0134 | 0.0112 | 0.012301 |
| RRF 0.80 image + 0.20 caption | 0.021943 | 0.005486 | 0.013714 |

Для RRF парная разность среднего NDCG@5 с image равна 0.002317;
95% cluster-bootstrap CI = [-0.001127, 0.007175]. Интервал включает ноль,
а лучший вариант выбран по этому же dev. Рост точечной оценки не доказывает
устойчивое улучшение на новых запросах. RRF также уступает learned на RU.

Средние скоры по каталогу на RU: image 0.2265, caption 0.8137, OCR 0.9409;
средние стандартные отклонения: 0.01261, 0.07402, 0.02866 соответственно.
Для отсутствующего текста признаки равны нулю. Прямое смешивание с весами
0.65/0.25/0.10 не сопоставляет распределения и создаёт предпочтения по
наличию и свойствам текста. Отмена перенормировки весов (linear_fixed)
почти не помогла; проблема не ограничивается знаменателем весов.

Особенно выражено предпочтение одной картинки в caption-ветке:
`nyu_75e688663401c7ca6af3c885`, описание «- Кванг Су. - Что?. неясно. анимация».
Она первая для 389/608 RU-запросов (64.0%) и 234/608 EN-запросов (38.5%).
Это измеренная концентрация выдачи; причину внутри текстового энкодера
одна эта статистика не устанавливает.

## Качество переводов и ограничения оценки

Найдены конкретные ошибки: `im a happy hippo` → «я счастливый хиппи»,
`arrest me` → «Заткнись!», `tongue out` → «язык вони».
JSON-валидация и устранение 47 зацикленных ответов проверяли формат и
полноту, а не корректность остальных 4124 переводов. RU-оценка содержит
ошибочные запросы. Средняя EN/RU cosine = 0.9684 не является проверкой
перевода: похожие векторы могут разделять общую составляющую.

Исходный протокол проверяет известные positive IDs. Другие потенциально
подходящие стикеры из каталога не размечены и считаются нулём. По запросу
`cat` найденная карточка по своему VLM-описанию тоже изображает кошку,
но не совпадает с единственным указанным positive. Это пример ограничения
разметки, а не человеческое подтверждение релевантности найденной картинки:
сами VLM-описания могут ошибаться.

Полный полученный архив сохранён в `evidence/full_v2/retrieval_diagnostics.zip`.
Новые эксперименты используют прежнюю версию запросов, чтобы отделить эффект
изменения поиска от исправления таргетов. Полную переработку переводов следует
оформить отдельной версией с проверкой качества по заранее выбранной выборке.

## Новый опыт

Первое изменение — оценить типичный скор каждой картинки по TRAIN-запросам:

    mean_q = mean(train_query_vectors)
    corrected_score(q, item) = q @ item - mean_q @ item

Поправка общая для всех последующих запросов. Никакие dev/test запросы,
положительные метки или популярность в dev-выдаче её не обучают. Вектора после
вычитания не нормируются: это корректировка скоров, а не новый cosine.
Гипотеза: она уменьшит преимущество текстов, близких сразу многим запросам.
RRF затем объединяет ранги, чтобы не смешивать напрямую разные шкалы.

Сравниваются заранее заданные методы:

- `rrf`: ранее проверенный вариант 0.80 image + 0.20 caption.
- `rrf_calibrated`: поправка только caption; image остаётся исходным.
- `rrf_calibrated_ocr`: поправка caption/OCR, веса 0.80/0.15/0.05.
- `rrf_calibrated_all`: поправка обеих используемых веток image/caption.
- `image_calibrated`, `caption_calibrated`: отдельные скорректированные ветки.

Второе сравнение — текстовая часть родного `clip-ViT-B-32` на исходном наборе
с меткой en и прежние image-векторы того же checkpoint. Текущий multilingual
энкодер — отдельная дистиллированная модель. Это контроль выбора энкодера,
а не готовое решение русского поиска. RU-строки не подменяются известными
оригиналами EN для получения искусственно хорошей RU-метрики. Набор en сам
содержит шумовые междометия и отдельные строки на других языках.

Модели уже входят в retrieval bundle, новые веса не требуются. Источник
описания архитектуры: [официальная карточка multilingual CLIP](https://huggingface.co/sentence-transformers/clip-ViT-B-32-multilingual-v1).

## Команда на поде

Загрузить `retrieval_v3_patch.zip` в корень проекта:

```bash
python -m zipfile -e retrieval_v3_patch.zip .
bash scripts/run_retrieval_v3.sh
```

Выходы — `runs/retrieval_v3`, лог — `runs/logs/retrieval_v3.log`.
Поправка и поиск работают на CPU; native CLIP кодирует запросы на `cuda:0`.
Файл для передачи результатов: `runs/retrieval_v3/results.zip`.
Test не оценивается. Прежние full_v2 данные/индекс/checkpoint не переписываются.
Повторный запуск остановится при уже существующей calibration; если процесс
упал позже, нужно продолжить конкретный оставшийся шаг из скрипта.

После выбора способа поиска `SearchIndex` поддерживает `method='rrf'`,
а для методов с поправкой принимает `calibration='runs/retrieval_v3/calibration'`.
Старые image/hybrid/lexical/learned сохраняют свои формулы. Новые методы пока
не выбраны как основной вариант демо и не объявлены улучшением.

Локально проведены десять CPU-тестов: точное воспроизведение прежнего RRF,
расчёт поправки, исключение dev/test/weak из её обучения, проверки индекса,
отсутствующих признаков, а также прежние тесты диагностики. Проверка native
CLIP с реальными весами и качество новых вариантов требуют запуска на поде.
