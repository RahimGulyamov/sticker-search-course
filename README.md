# Поиск стикеров и открыток: SigLIP 2

Итоговый проект по компьютерному зрению. По русскому или английскому запросу
система ищет изображения в каталоге из **30 914 объектов**. Дополнительно
доступны две независимые функции: **генерация изображения** через FLUX.1-schnell
и **удаление фона** через U²-Net / rembg.

Основной эксперимент — **полное дообучение SigLIP 2 SO400M** на четырёх A100
80 GB. Обновляются обе башни, всего 1 136 008 498 параметров.
Первая версия с CLIP и малыми адаптерами сохранена как baseline.

## Подтверждённые результаты

| Модель | NDCG@5 EN | NDCG@5 RU | Hit@10 EN | Hit@10 RU |
|---|---:|---:|---:|---:|
| Исходная SigLIP 2 | 0,0495 | 0,0149 | 8,38% | 2,79% |
| Дообученная, эпоха 2 | **0,0923** | **0,0658** | **17,94%** | **12,50%** |

Эпоха выбрана по среднему EN/RU NDCG@5 на dev: **0,08693**. На третьей эпохе
train loss продолжил снижаться, а dev ухудшился до 0,08361. Исходные результаты:
[evidence/siglip2](evidence/siglip2/). Обучение: 3 эпохи, 1 158 шагов, global batch
128, AdamW 5e-6, BF16 autocast, gradient checkpointing.

**Границы оценки:** 680 запросов на язык, 86 уникальных целевых стикеров;
поиск по всему каталогу. RU — машинные переводы исходных запросов. Обычно
размечен один правильный ответ, а не все релевантные изображения. Этот test
ранее уже использовался для CLIP. Здесь он не использовался для выбора эпохи
SigLIP. Качество открыток и отдельной OCR-ветви этим тестом не подтверждается.

## Данные

| Источник | Число изображений | Заявленная лицензия |
|---|---:|---|
| nyuuzyou/stickers | 30 000 | WTFPL |
| StickerQueries | 574 | MIT |
| Synth-GCD | 100 | Apache-2.0 |
| Композиции с OpenMoji | 240 | CC-BY-SA-4.0 |

Каталог содержит 30 574 стикера и 340 открыток. Разбиение по группам:
train 21 805, dev 4 469, test 4 640. Для обучения использованы **21 776**
train-изображений (99,87% доступной train-части) и **49 318 пар**: 43 552
автоматических описания EN/RU, 2 883 исходных запроса и 2 883 перевода.
Dev/test-изображения не используются для градиентов и отрицательных пар.

Qwen2.5-VL создаёт визуальные подписи и OCR. Это слабая автоматическая разметка,
которая может ошибаться. `usage_queries_ru` не используются для обучения SigLIP.
Проверки файлов, хешей и групп близких изображений описаны в
[README_CLIP.md](README_CLIP.md). Источники и атрибуция сохраняются в
[evidence/full_catalog](evidence/full_catalog/). Лицензия набора не доказывает
наличие прав на каждого изображённого стороннего персонажа.

## Архитектура

- Два Transformer-энкодера SigLIP 2, вход изображения 384×384, векторы 1 152.
- Нормированные признаки каталога вычисляются заранее. Текст кодируется при
  запросе; точный поиск выполняется скалярным произведением со всем каталогом.
- Обучение: взвешенный multi-positive sigmoid loss. Негативы из общего текущего
  батча четырёх GPU, differentiable all_gather, маскирование неопределённых пар
  одной группы, учёт повторов картинок.
- OCR: отдельное объединение рангов визуального поиска и символьного TF-IDF.
  Основные метрики выше относятся к поиску без этой дополнительной ветви.
- Генерация: Qwen переводит запрос → FLUX.1-schnell создаёт исходник за 4 шага.
  Отдельная кнопка U²-Net удаляет фон на CPU. Модели этой ветви не дообучались.

Подробности: [SigLIP 2](docs/SIGLIP2.md),
[две функции генерации](docs/GENERATION_STEPS.md).

## Запуск на уже подготовленном поде

```bash
cd /home/jovyan/sticker_search
source configs/pod.env
source configs/offline.env
export CUDA_VISIBLE_DEVICES=0
export STICKER_SIGLIP_RUN=/tmp/cv_project/siglip2_v1
export STICKER_ENABLE_GENERATION=1
python -m streamlit run app_siglip2.py \
  --server.address 127.0.0.1 --server.port 8501 --server.headless true \
  --browser.gatherUsageStats false
```

В VS Code перенаправьте порт **8501** во вкладке **Ports**. Требуются локальный
каталог `data/catalog`, обученный run с `selection.json`, checkpoint и индексом,
а для генерации — заранее перенесённые Qwen, FLUX и U²-Net. Git-репозиторий
не содержит этих больших файлов. Повторять обучение на готовом поде не нужно.

## Установка и воспроизведение с нуля

Linux, Python 3.10–3.12. Эталонный GPU-профиль: torch 2.9.1+cu128,
transformers 4.57.1, четыре A100 80 GB. Код использует точные ревизии моделей
из `configs/model_revisions.json` и `configs/siglip2_full.json`.

На машине **с интернетом**, при подготовке новой среды:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements/cuda-cu128.txt --index-url https://download.pytorch.org/whl/cu128
python -m pip install -e '.[demo,generation,yt,test,report]'
python -m pytest -q
cp configs/pod.env.example configs/pod.env
```

Настройте личные YT-пути в `configs/pod.env`; этот файл исключён из Git.
Не заменяйте существующий рабочий файл на поде шаблоном.
На Mac публикация кода не требует установки torch или остальных ML-пакетов.

1. Восстановление исходного каталога с проверкой хешей:
   `python -m sticker_search.restore_catalog --output data/catalog`.
2. Перенос каталога и весов через YT:
   [OFFLINE_TRANSFER.md](docs/OFFLINE_TRANSFER.md).
3. Разметка caption/OCR и переводы: команды из
   [предыдущего runbook](README_CLIP.md), затем `bash scripts/run_gpu.sh`.
   Этот скрипт также выполняет старый CLIP baseline.
4. Полное дообучение обеих башен: `bash scripts/run_siglip2.sh`.
   Подготовка весов, пути, resume и ограничения описаны в
   [SIGLIP2.md](docs/SIGLIP2.md).
5. После фиксации выбора по dev:

```bash
python -m sticker_search.siglip.evaluate --run /tmp/cv_project/siglip2_v1 \
  --which baseline --split test --allow-test
python -m sticker_search.siglip.evaluate --run /tmp/cv_project/siglip2_v1 \
  --which selected --split test --allow-test
```

На поде без интернета веса и зависимости должны быть перенесены заранее.
Рабочую CUDA-сборку не переустанавливайте. `/tmp` может пропасть вместе с подом:
сохраните checkpoint и индекс отдельно в YT. Прямые зависимости закреплены;
полного lock-файла всех транзитивных пакетов GPU-среды в проекте нет.
